# Plan: Real-World Proof + Demo — face-scout

**Date:** 2026-07-20 · **Status:** awaiting go · **Executor:** any capable agent (self-contained — no session context required)
**Branch state:** work lives on `autopilot/work` (Phases 1–2 code-complete, 74 tests green, ruff clean). Continue from there on a new branch.

## Context (verified 2026-07-20 by code review)

face-scout is a staged webcam CV project: Phase 1 = tracking (greedy-IoU + occlusion coasting), MediaPipe 468-point face mesh, InsightFace/ArcFace identity vs. a local gallery; Phase 2 v1 = lip reading (`lips record/train/eval/run`, RandomForest on normalized/resampled lip-landmark sequences, session-aware split). Architecture is the strong part: pure-logic core behind `Protocol` seams (`src/face_scout/types.py` — `FrameSource`, `Landmarker`, `Embedder`), thin `app.py`, focused modules (~1300 LOC).

**The defining gap: zero real-world proof.** All 74 tests use fakes or synthetic arrays. No test ever instantiates `MediaPipeLandmarker`/`InsightFaceEmbedder` on a real image. No real lip-reading recording exists — the 80–95% accuracy in `docs/adr/0001-lip-reading-approach.md` is literature extrapolation, never measured. `assets/` is empty (no screenshot, no GIF). The camera-free `--video` path (Milestone 6) exists but never ran on real footage. `docs/superpowers/plans/` is empty; specs live in `docs/superpowers/specs/`.

Environment facts an executor can rely on: `mediapipe`, `insightface`, `onnxruntime`, `cv2` are installed and importable in this WSL environment. Live camera windows are impossible here (headless; `libGLESv2.so.2` missing for the GUI path) — but image/video-file processing may still work; that boundary is exactly what Phase B probes.

Hard project principles (do not violate):
- Biometric artifacts (gallery `.npz`, lip model `.joblib`, personal recordings) are never committed. Extend this to fixtures of real people: **fixtures stay git-ignored**, fetched/generated by script.
- Honest verification boundary: "imports cleanly" ≠ "works". Every claim in README must state how it was proven. "Needs Nico" is a first-class status.
- No new heavyweight dependencies without a note in the outcome section (`imageio` for GIF writing is acceptable if `cv2.VideoWriter` proves awkward).

## Goal

Close the gap between "clean code that has never seen a face" and "provably working CV system": real-inference tests on fixture media, a generated demo GIF, a measured (not estimated) lip-reading accuracy report, a one-command demo any cloner can run without a webcam — plus the small robustness fixes the review found in the live loops.

## Execution rules

- New branch `feat/real-world-proof` off `autopilot/work`. Conventional Commits, English, small and atomic.

## Phase A — Robustness fixes (no hardware needed)

### Task 1: Config paths overridable, CWD-decoupled
**Files:** `src/face_scout/config.py`, tests.
`MODELS_DIR`/`GALLERY_DIR` are relative module-level `Path` constants — the program only works when started from repo root. Make each overridable via env (`FACE_SCOUT_MODELS_DIR`, `FACE_SCOUT_GALLERY_DIR`), default unchanged. Read env at call time (small accessor functions), not import time, so tests can monkeypatch.
**Accept:** tests prove env override + default; all existing tests green.

### Task 2: Error boundary around hardware calls in live loops
**Files:** `src/face_scout/app.py::run`, `src/face_scout/lips/live.py::run_live`, `src/face_scout/enroll.py`, tests.
A single MediaPipe/InsightFace exception (corrupt frame, camera disconnect) currently crashes the whole loop. Catch per-frame exceptions around `landmarker.detect()`/`embedder.embed()`, log via `logging` (module logger, no print), count consecutive failures, abort cleanly after a configurable threshold (default 30) instead of looping forever on a dead camera.
**Accept:** unit test with a fake landmarker that throws intermittently → loop continues; throws persistently → clean abort with message.

### Task 3: Camera buffer latency fix
**Files:** `src/face_scout/capture.py::WebcamCapture.__init__`.
Set `self._cap.set(cv2.CAP_PROP_BUFFERSIZE, 1)` (ignore unsupported-property failures silently — cv2 returns False, doesn't raise). One-line fix for latency drift when processing runs slower than camera FPS; comment states the why.
**Accept:** existing capture tests green (property is a no-op on file sources).

### Task 4: Extract `EnrollmentSession` (testable enrollment core)
**Files:** new `src/face_scout/enrollment.py`, `src/face_scout/enroll.py`, tests.
Mirror the `pipeline.py` refactor pattern: pull decision logic (which shots are collected, what happens on capture key, when enrollment is complete) out of the camera loop into a pure `EnrollmentSession` class. While at it, throttle embedding to every Nth frame (reuse the `recognize_every` idiom from `config.py`) — currently InsightFace runs on every frame during enrollment.
**Accept:** enrollment decision logic fully unit-tested with fakes; `enroll.py` becomes a thin loop like `app.py`.

### Task 5: Renderer tests
**Files:** `tests/test_renderer.py` (new).
`renderer.py` draws overlays on ndarrays — testable without any display. Assert: drawing changes pixels within the expected bounding region, leaves the rest untouched, handles zero-face frames, and label text rendering doesn't raise on edge positions (top row, image border).
**Accept:** renderer no longer in the "completely untested" list.

## Phase B — Real inference proof (no camera)

### Task 6: Fixture infrastructure
**Files:** new `scripts/fetch_fixtures.py`, `tests/fixtures/` (git-ignored — add to `.gitignore`), `tests/conftest.py` (skip-if-missing helpers), README note.
Provide two fixtures via script, never committed:
1. **Static face image** — decision tree, stop at first success: (a) `skimage.data.astronaut()` if scikit-image installs cleanly as dev-dep (512×512, public domain NASA portrait, MediaPipe detects it in common tutorials); (b) a single LFW image via `sklearn.datasets.fetch_lfw_people(color=True, resize=1.0)` (sklearn already a dependency); (c) documented manual drop-in path. Acceptance for the chosen branch: `MediaPipeLandmarker` returns 468 landmarks on it.
2. **Talking-face clip (~5–15s)** — decision tree: (a) scripted download of one openly licensed talking-head clip (document URL + license in the script; check the GRID audiovisual speech corpus first — single-speaker video subsets are freely downloadable — then any CC0/CC-BY talking-head source); (b) if no reliable machine-fetchable source: generate `tests/fixtures/talking_face.avi` by animating the static face image (affine mouth-region warping keyed to a viseme schedule) — mark it clearly as synthetic-from-real-photo; MediaPipe must still detect ≥90% of frames, else this branch fails; (c) final fallback: Needs-Nico records one 10s clip (goes on the punch list, Phase B tasks 7–8 then run against it later).
**Accept:** `uv run python scripts/fetch_fixtures.py` is idempotent and prints what it fetched/generated + license; conftest exposes `require_face_image`/`require_talking_clip` skip helpers.

### Task 7: Adapter smoke tests against real inference
**Files:** `tests/test_adapters_real.py` (new, `@pytest.mark.real`).
First-ever tests instantiating the real adapters: `MediaPipeLandmarker.detect()` on the fixture image → 468 landmarks, plausible coordinate ranges, deterministic across two calls; `InsightFaceEmbedder.embed()` → 512-dim vector, near-unit norm, cosine-similar to itself across two runs, dissimilar to a face-free noise image (expect detection failure or None — assert the adapter's actual contract).
If MediaPipe image-mode fails in this sandbox due to missing GL libs: document the exact error in the test's skip reason and in the outcome section — that itself is valuable verification data. Do not fake a pass.
**Accept:** the "we never confirmed the real libraries produce plausible outputs" gap is closed (or the sandbox blocker is precisely documented).

### Task 8: Fixture-video end-to-end run
**Files:** `tests/test_e2e_video.py` (new, `@pytest.mark.real`), possibly small fixes in `pipeline.py`/`capture.py` that the first real run flushes out.
Run the full Phase-1 pipeline (`build_pipeline` + `VideoFileSource`) over the talking clip: assert ≥1 stable track over the clip, landmarks present on most frames, no crash, and (with an empty gallery) identity honestly "unknown". This is the moment the project first processes real footage — expect and fix small breakages; that is the point of the task.
**Accept:** `face-scout run --video tests/fixtures/<clip>` completes headlessly (add a `--no-display` flag if `cv2.imshow` is the only blocker — write annotated frames to disk instead).

## Phase D — Measured lip-reading accuracy (kill the literature estimate)

### Task 11: Real dataset + honest accuracy report
**Files:** `scripts/fetch_lip_data.py` (new), `docs/lip-reading-eval.md` (new), README section, ADR 0001 addendum.
Decision tree, stop at first workable branch:
1. **GRID corpus subset**: scripted download of 1 speaker's video subset (free for research; verify the current mirror in-script), extract 3–5 short command words, ≥20 clips/word, run the real `lips record --video`-equivalent ingestion (feed clips through the MediaPipe path into `lips/dataset.py`), then `lips train` + `lips eval` with the existing session-aware split (treat GRID's natural grouping as sessions).
2. If GRID is not machine-fetchable anymore: any other openly licensed word-level lipreading set that is.
3. Fallback: generate the ingestion + eval harness fully, run it on the synthetic clip from Task 6b as a pipeline-proof (clearly labeled "pipeline verified, accuracy pending real data"), and put the 15-minute recording session on the Needs-Nico punch list.
Report in `docs/lip-reading-eval.md`: dataset provenance + license, sample counts, confusion matrix, measured accuracy vs. the ADR's 80–95% estimate, and one paragraph on the feature-to-sample ratio (2560 features at `length=32` vs. sample count — if measured accuracy is weak, run one comparison at `length=16` and report both; do not tune further).
**Accept:** README's accuracy claim links to a measured number with provenance — or is explicitly labeled "pending real data" with the harness proven. Never present synthetic numbers as real accuracy.
